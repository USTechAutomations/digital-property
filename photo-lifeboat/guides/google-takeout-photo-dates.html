Google Takeout photos with the wrong date: how to fix them

When you download your Google Photos with Google Takeout, the date your computer shows for each photo can be wrong, and a pile of extra .json files comes along. This guide explains why and walks through the free fixes first.

The short answer

The dates are usually not lost. A popular free helper explains that Takeout gives you ZIP files full of small folders with strange .json files inside, and that it fixes each file's "last modified" date. The same helper says most photos should still carry their original date inside the picture file itself.

So the job has two parts: gather the photos into one place, and put the date Google kept back onto each file. Free tools do this. Use one of them if you are comfortable typing commands.

What you are looking at

Google's help page says you can export Google products, including Photos, from the Google Takeout page. It offers ZIP files, and if your data is bigger than the archive size you choose, it makes several archives. So one library often arrives as many ZIP files.

The helper's README describes what you find when you open them: hundreds of little folders with .json files inside. Those files are the extra details Google keeps next to each photo. They are not photos, so do not delete them until your dates are fixed.

The date a file manager shows is the file's last-modified date. That is a different thing from the date stored inside a photo. This is why a photo can look wrong in a folder while the picture itself still knows when it was taken.

The steps

  1. Keep every original ZIP file. The helper's README says to keep them in case anything goes wrong.
  2. When you ask Google for the export, pick only Google Photos. The README says to "deselect all" and then select only Google Photos.
  3. Unzip all the parts and merge them so every Takeout folder becomes one.
  4. Run a helper (next section) to gather the photos and set the dates.
  5. Check a handful of photos in the result. If some look wrong, go back to the ZIP files you kept.

The free ways

Google Photos Takeout Helper

Its README says it takes all those folders, finds the photos, sets each file's last-modified date correctly, and puts everything in one big folder, or folders divided by month. You download a program for your system from its releases tab and run it. On Windows the README says to double-click it; on Mac and Linux you run it from a terminal. It says the helper moves files by default, which is another reason to keep the ZIP files.

ExifTool

ExifTool's home page calls it a platform-independent Perl library plus a command-line application for reading, writing and editing meta information in many kinds of files. The helper's README suggests it as a second step if you want the date written inside the photos too, so you do not lose the creation time. This is the command the README gives for that:

exiftool -overwrite_original -r -if 'not defined DateTimeOriginal' -P "-AllDates<FileModifyDate" "your/output/folder/ALL_PHOTOS/"

The README adds a warning: do not touch the files after running the helper, or the file dates the command reads may change. Read the README itself before running anything.

Both tools are free. Both are made by other people, and we are not rating them.

Where our tool fits, and what it cannot do

Photo Lifeboat is a $29 one-time tool that is one HTML file you open in Chrome or Edge on a Windows, Mac or Linux computer. You choose your Takeout ZIP files and an empty folder. It reads the ZIPs a piece at a time and never changes them. It matches each photo to Google's details file and builds a folder with your photos filed by year and month, a page for each album, and an album viewer that opens with no internet. Nothing is uploaded.

On dates: it writes the date Google had stored back into JPEG files that had none. Other file types are left exactly as Google exported them. Their date is kept in a list and in the viewer, not written into the file. It also makes a list of anything it could not match, and it never guesses a date. Dates are in UTC, because Google does not store the time zone.

What it cannot do: it does not run in Safari, Firefox or on phones. It cannot recover photos that were never in your Google download. Some formats, such as HEIC, may not show in its viewer. We have tested it only on a small made-up Takeout, not yet on large real exports, and you can open a finished sample album first.

If the free tools above already give you what you need, you do not need ours.
